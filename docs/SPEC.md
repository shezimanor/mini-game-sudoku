# 數獨遊戲 規格書（Specification）

> 狀態：草稿 v1.3
> 最後更新：2026-09-16
> 技術棧：React 19 + TypeScript + Vite

---

## 1. 文件目的

本文件定義本專案「數獨遊戲」的功能規格，涵蓋難度選擇、題目產生、遊戲互動、計時、暫停、判定與結束流程。

本文件採漸進式撰寫：先記錄已確定的需求，未確定處以 `TBD`（待定）標註，避免過早鎖死設計。

---

## 2. 名詞定義

| 名詞 | 說明 |
| --- | --- |
| 盤面（Board） | 9×9 的數獨格子，共 81 格 |
| 宮（Box） | 盤面中 3×3 的區塊，共 9 個 |
| 正解（Solution） | 該題完整且唯一的 81 格答案 |
| 初始題目（Puzzle） | 一開始就填好、玩家不可更動的數字（給定數字 / Givens） |
| 空格（Empty Cell） | 玩家需要填入數字的格子 |
| 鎖定格（Locked Cell） | 不可再被選取或修改的格子：初始題目 + 已填對的格子 |
| 難度（Difficulty） | 決定初始題目給定數字多寡的等級 |
| 數字面板（Number Pad） | 點選空格後彈出的 1–9 數字按鈕面板 |
| 彈窗（Modal） | 置中的對話框，外圍帶模糊遮罩，見 §5 |
| 一局（Round） | 一份題目的一次遊玩，含計時與 3 次答錯機會 |
| 開始畫面 | 即難度選擇畫面（S1），兩者為同一個畫面 |

## 3. 範圍

### 3.1 本版本涵蓋（In Scope）

1. 難度選擇（簡單 / 中等 / 困難）。
2. 依難度以演算法即時產生唯一解數獨題目，含 skeleton loading。
3. 遊戲畫面：盤面、難度、計時器、剩餘答錯次數、暫停鍵。
4. 點選空格 → 數字面板（含鍵盤輸入）→ 填入數字。
5. 填入後即時判定，錯誤有動畫回饋並扣除機會，三次用盡即結束。
6. 暫停功能與暫停彈窗。
7. 完成彈窗（顯示總時間）與失敗彈窗。
8. 重新開始（同題重玩）、另開新局（同難度新題）、重選難度（回開始畫面）。

### 3.2 本版本不涵蓋（Out of Scope）

- 清除已填數字、筆記（小數字）等進階輸入行為
- 提示（Hint）、悔棋（Undo）
- 遊戲進度儲存 / 讀取、跨場歷史成績
- 排行榜、帳號系統、多語系

## 4. 畫面與流程

### 4.1 畫面清單

| 代號 | 畫面名稱 | 呈現形式 | 說明 |
| --- | --- | --- | --- |
| S1 | 開始畫面（＝難度選擇畫面） | 彈窗 | 進入網頁的預設畫面，三個難度按鈕 |
| S2 | 遊戲畫面 | 主畫面 | HUD + 9×9 盤面 |
| S3 | 載入中畫面 | 主畫面 | 產題期間的 skeleton loading |
| M1 | 暫停彈窗 | 彈窗 | 繼續遊戲 / 重新開始 / 重選難度 |
| M2 | 完成彈窗 | 彈窗 | 完成提示 + 總時間 + 另開新局 / 重選難度 |
| M3 | 失敗彈窗 | 彈窗 | 失敗提示 + 重新開始 / 重選難度 |
| M4 | 錯誤彈窗 | 彈窗 | 產題失敗提示 + 我知道了 |

### 4.2 主要流程

```
[進入網頁]
     │
     ▼
  S1 開始彈窗「Welcome Sudoku」（簡單 / 中等 / 困難）
     │  點擊難度按鈕
     ▼
  S3 載入中（skeleton，點擊無效）
     │  題目產生完成                    連續 3 次產題失敗
     │                                      └─▶ M4「Error」─ 我知道了 ─▶ 回 S1
     ▼
  S2 遊戲畫面（計時開始）
     │
     ├── 點擊暫停 ──▶ M1「Menu」──┬─ 繼續遊戲 ─▶ 回 S2
     │                            ├─ 重新開始 ─▶ 同題重置，回 S2
     │                            └─ 重選難度 ─▶ 回 S1
     │
     ├── 全部填對 ──▶ M2「Congratulations!」（總時間）
     │                    ├─ 另開新局 ─▶ 同難度產生新題目，回 S3
     │                    └─ 重選難度 ─▶ 回 S1
     │
     └── 答錯 3 次 ─▶ M3「Oops!」
                          ├─ 重新開始 ─▶ 同題重置，回 S2
                          └─ 重選難度 ─▶ 回 S1
```

### 4.3 狀態模型

| 狀態 | 意義 | 計時 | 可輸入 | 顯示 |
| --- | --- | --- | --- | --- |
| `idle` | 尚未選擇難度 | — | 否 | S1 |
| `generating` | 產題中 | 未開始 | 否 | S3 |
| `playing` | 遊戲進行中 | 進行 | 是 | S2 |
| `paused` | 已暫停 | 暫停 | 否 | S2（遮罩）+ M1 |
| `completed` | 全部填對 | 停止 | 否 | S2 + M2 |
| `gameOver` | 三次機會用盡 | 停止 | 否 | S2 + M3 |
| `error` | 產題連續失敗 | — | 否 | M4 |

## 5. 彈窗系統（共用）

- **FR-0.1** 所有彈窗（S1 / M1 / M2 / M3）採用**一致**的呈現方式：置中對話框，內含按鈕，外圍為**模糊遮罩**覆蓋整個畫面。
- **FR-0.2** 模糊遮罩需確保玩家**無法看清後方的盤面內容**（暫停時尤其重要，避免玩家暫停後繼續看題思考）。
- **FR-0.3** 彈窗開啟期間，後方畫面（盤面、HUD、數字面板）一律不可互動。
- **FR-0.4** 彈窗只能由其內部按鈕關閉；點擊遮罩、按 Esc 不關閉彈窗。
- **FR-0.5** 各彈窗的文案與按鈕（已定案）：
  | 彈窗 | 標題 | 內文 | 按鈕 |
  | --- | --- | --- | --- |
  | S1 開始 | `Welcome Sudoku` | — | 簡單 / 中等 / 困難 |
  | M1 暫停 | `Menu` | — | 繼續遊戲 / 重新開始 / 重選難度 |
  | M2 完成 | `Congratulations!` | 該局完成總時間（`hh:mm:ss`） | 另開新局 / 重選難度 |
  | M3 失敗 | `Oops!` | — | 重新開始 / 重選難度 |
  | M4 錯誤 | `Error` | — | 我知道了 |
  > 標題為英文原文，不另做翻譯；按鈕為中文。
  > M3 失敗彈窗**不顯示**已用時間。
  > M4 錯誤彈窗**不顯示**額外說明文字，僅標題與按鈕。
- **FR-0.6** 共用按鈕語意：
  | 按鈕 | 行為 | 出現於 |
  | --- | --- | --- |
  | 繼續遊戲 | 關閉彈窗，計時從暫停處繼續，回到 `playing` | M1 |
  | 重新開始 | **同一題重玩**：保留目前題目，清空玩家已填入的數字，計時歸零重新開始，答錯機會重置為 3 次 | M1、M3 |
  | 另開新局 | **同難度產生新題目**：不回到開始畫面，直接以目前難度重新產題（進入 `generating`，顯示 skeleton），完成後計時歸零、答錯機會重置為 3 次 | M2 |
  | 重選難度 | 回到 S1 開始彈窗（`idle`），玩家重新選擇難度後產生新題目 | M1、M2、M3 |
  | 我知道了 | 關閉錯誤彈窗，回到 S1 開始彈窗（`idle`） | M4 |
- **FR-0.7** 彈窗與遮罩的視覺樣式見 §9.6。

## 6. 功能需求：難度選擇與題目產生

### 6.1 難度選擇（S1）

- **FR-1.1** 玩家開啟網頁時，預設顯示開始彈窗（S1），標題為 `Welcome Sudoku`。開始畫面即難度選擇畫面，兩者為同一個畫面。
- **FR-1.2** 彈窗內提供**三個**難度按鈕（簡單 / 中等 / 困難），並列呈現，視覺樣式一致，僅文字不同。
- **FR-1.3** 三個難度：
  | 代號 | 顯示文字 | 給定數字數量 | 空格數量 |
  | --- | --- | --- | --- |
  | `easy` | 簡單 | 40–45 | 36–41 |
  | `medium` | 中等 | 32–36 | 45–49 |
  | `hard` | 困難 | 26–30 | 51–55 |
  > 每場遊戲在該難度的區間內隨機取一個給定數字數量，避免每局題目密度完全相同。
  > 數獨題目要維持唯一解，給定數字至少需 17 個，因此 `hard` 的下限 26 仍留有安全餘裕。
  > 本專案採「填錯即扣機會、僅 3 次」的規則，難度整體較一般數獨稍微寬鬆一級。
- **FR-1.4** 進入網頁時不預先產生任何盤面；盤面僅在玩家選擇難度後才產生。
- **FR-1.5** 點擊任一難度按鈕後，S1 彈窗（含標題、三個按鈕與遮罩）關閉，進入 `generating`。

### 6.2 載入中狀態（S3）

- **FR-2.1** 產題期間顯示 **skeleton loading**：以 9×9 的骨架方塊呈現盤面輪廓，HUD 區域亦以骨架呈現。
- **FR-2.2** skeleton 需帶有律動效果（如 shimmer / pulse），表示系統正在處理。
- **FR-2.3** 載入期間**玩家的任何點擊皆無效**，不接受任何輸入。
- **FR-2.4** 載入期間計時器**不啟動**。
- **FR-2.5** 題目產生完成後，skeleton 換成實際盤面，進入 `playing` 並開始計時。
- **FR-2.6** skeleton 的**最短顯示時間為 600ms**：即使題目在更短時間內產生完成，仍須顯示滿 600ms 才切換到盤面，避免畫面閃爍。
- **FR-2.7** 若產題耗時超過 600ms，則以實際完成時間為準，skeleton 持續顯示至產題結束。

### 6.3 題目產生

- **FR-3.1** 題目由**前端演算法即時產生**，不使用內建題庫。
- **FR-3.2** 產生流程建議如下：
  1. 以回溯法（backtracking）+ 隨機順序產生一個完整且合法的 9×9 正解；
  2. 以隨機順序逐一挖空格子；
  3. 每挖一格即用解題器驗證剩餘盤面**是否仍為唯一解**，若不是則還原該格；
  4. 直到給定數字數量達到該難度的目標值。
- **FR-3.3** 產生的題目**必須具備唯一解**（強制）。
- **FR-3.4** 正解需完整保留於記憶體中，作為 §7.4 即時判定的比對基準。
- **FR-3.5** 每列、每行、每宮的 1–9 不得重複。
- **FR-3.6** 每次產題皆為隨機，重複遊玩不應固定得到同一題。
- **FR-3.7** 若挖空過程無法達到目標給定數字數量，則以當下可達的最少給定數字為準，不得犧牲唯一解。

## 7. 功能需求：遊戲互動

### 7.1 遊戲畫面資訊列（HUD）

- **FR-4.1** 遊戲畫面上方設資訊列，分左右兩區：
  | 位置 | 顯示內容 |
  | --- | --- |
  | 左上角 | 目前難易度（簡單 / 中等 / 困難）、計時器 |
  | 右上角 | 答錯機會剩餘次數、暫停鍵 |
- **FR-4.2** 難易度顯示玩家在 S1 所選的難度，一局之中不會改變。
- **FR-4.3** 資訊列在整場遊戲中持續顯示。

### 7.2 計時器

- **FR-5.1** 題目產生完成、盤面顯示後立即開始計時。
- **FR-5.2** 計時器即時更新，顯示格式為 **`hh:mm:ss`**。
- **FR-5.3** 暫停時計時暫停，繼續遊戲時從暫停處接續。
- **FR-5.4** 遊戲結束（完成或三次機會用盡）時計時停止。
- **FR-5.5** 「重新開始」時計時歸零重新計算。
- **FR-5.6** 每場遊戲的總時間僅供**該場結束時顯示**使用，不跨場保存、不累積歷史紀錄。

### 7.3 暫停（M1）

- **FR-6.1** 暫停鍵位於畫面右上角，僅在 `playing` 狀態可用。
- **FR-6.2** 點擊暫停鍵後：計時暫停、盤面停止接受輸入、數字面板若開啟則關閉、顯示暫停彈窗 M1。
- **FR-6.3** 暫停彈窗外圍的模糊遮罩需遮蔽盤面，使玩家**無法在暫停期間繼續看題**（見 FR-0.2）。
- **FR-6.4** 暫停彈窗標題為 `Menu`，內含三個按鈕：**繼續遊戲**、**重新開始**、**重選難度**，行為見 FR-0.6。

### 7.4 選格與數字輸入

- **FR-7.1** 玩家以滑鼠左鍵點選一個**空格**進行選取。
- **FR-7.2** 選取空格後，於該空格旁彈出 3×3 排列的數字按鈕面板（1–9）。
- **FR-7.3** 面板方位採**邊緣判斷**：
  1. 預設顯示於空格**下方**；
  2. 空格靠近畫面底部、下方空間不足時，改顯示於空格**上方**；
  3. 左右方向同理，必要時向內位移，確保面板完整落在可視範圍內；
  4. 原則是**面板不得遮住被選取的空格本身**。
- **FR-7.4** 面板的關閉時機：
  1. 點選面板上的數字 → 填入後**立即關閉**（不論答對或答錯）；
  2. 點擊該目標空格與面板**以外的任何地方** → 直接關閉面板，不填入任何數字；
  3. 進入暫停、完成或失敗狀態時自動關閉。
- **FR-7.5** 支援鍵盤輸入數字，但**前提是數字面板已開啟**：玩家須先以左鍵點選空格開啟面板，才能按 1–9 鍵填入該空格；面板未開啟時鍵盤輸入無效。
- **FR-7.6** 鍵盤輸入與點選數字按鈕的後續行為完全相同（填入、關閉面板、進入即時判定）。
- **FR-7.7** 鎖定格（初始題目、已填對的格子）不可被選取，點選時不會開啟數字面板。

### 7.5 即時判定

- **FR-8.1** 玩家填入數字後，系統**立即**以該題正解為基準判定該數字是否正確（非僅檢查是否違反數獨規則）。
- **FR-8.2** 判定正確：數字保留在格子中，該格成為鎖定格不可再修改（視覺上仍可與初始題目區分）。
- **FR-8.3** 判定錯誤：扣除一次答錯機會，右上角剩餘次數更新，並播放 FR-8.4 的錯誤動畫，動畫結束後該格恢復為空格。
- **FR-8.4** 錯誤動畫時序（以填入瞬間為 T=0）：
  | 時間點 | 行為 |
  | --- | --- |
  | T = 0 | 玩家填入的數字先**正常顯示**在空格中 |
  | T = 0.3s | 數字被**紅色 X** 取代 |
  | T = 0.3s – 0.9s | 紅色 X 播放 **headShake** 動畫（0.6s） |
  | T = 0.9s – 1.2s | 紅色 X **淡出**（0.3s） |
  | T = 1.2s | X 消失，該格恢復為空格，可再次作答 |
- **FR-8.5** 答錯次數的扣除時間點為 T = 0.3s（紅色 X 出現的同時），與視覺回饋同步。
- **FR-8.6** 錯誤動畫播放期間，該格暫時不可再被選取；其他格子仍可正常操作。
- **FR-8.7** 若該次錯誤使剩餘機會歸零，錯誤動畫**播放完畢後**（T = 1.2s）才顯示失敗彈窗 M3。

### 7.6 答錯機會與失敗（M3）

- **FR-9.1** 每一局固定有 **3 次**答錯機會。
- **FR-9.2** 每次填入錯誤數字扣除 1 次機會。
- **FR-9.3** 剩餘次數歸零時，該局結束：計時停止、盤面不再接受輸入。
- **FR-9.4** 顯示失敗彈窗 M3，標題為 `Oops!`，下方兩個按鈕：**重新開始**、**重選難度**（行為見 FR-0.6）。
- **FR-9.5** 失敗彈窗**不顯示**該局已用時間。
- **FR-9.6** 失敗後**不顯示正解**，後方盤面維持玩家結束當下的狀態（僅被模糊遮罩覆蓋）。

### 7.7 完成（M2）

- **FR-10.1** 盤面上所有空格皆填入正確數字時，該局判定為**完成**。
- **FR-10.2** 完成時計時停止，盤面不再接受輸入。
- **FR-10.3** 顯示完成彈窗 M2，標題為 `Congratulations!`，內文顯示該局**總時間**（`hh:mm:ss`），下方兩個按鈕：**另開新局**、**重選難度**（行為見 FR-0.6）。
- **FR-10.4** 完成彈窗**不提供**「重新開始」（同題重玩）；題目已解完，重玩同一題無意義。

### 7.8 產題失敗（M4）

- **FR-20.1** 產題連續失敗達 FR-19.7 的次數上限時，進入 `error` 狀態。
- **FR-20.2** 顯示錯誤彈窗 M4，標題為 `Error`，**不顯示額外說明文字**，僅一個按鈕：**我知道了**。
- **FR-20.3** 點擊「我知道了」後關閉彈窗，回到 S1 開始彈窗（`idle`），玩家可重新選擇難度。
- **FR-20.4** 此狀態下不顯示盤面與 HUD。

## 8. 非功能需求

- **NFR-1 效能**：產題（含唯一解驗證）應在可接受時間內完成；若超過感知門檻，由 skeleton loading 承接（見 §6.2）。逾時門檻見 FR-19.7。
- **NFR-2 效能**：產題運算一律在 Web Worker 執行，不得凍結 UI，見 §10.1。
- **NFR-3 相容性**：支援主流桌面瀏覽器最新版（Chrome / Edge / Safari / Firefox）。
- **NFR-4 響應式**：盤面在桌機與行動裝置上皆可完整顯示、不需橫向或垂直捲動，尺寸規則見 §9.9。
- **NFR-5 可及性**：按鈕與格子具備可辨識的語意標記，支援鍵盤聚焦（細節 TBD）。
- **NFR-6 動畫與無障礙**：動畫時長依 FR-8.4；支援 `prefers-reduced-motion`，替代方案見 §9.8。
- **NFR-7 技術限制**：純前端實作，無後端伺服器，不儲存玩家資料。

## 9. 視覺規格

風格定案：**現代深色（Modern Dark）**。深藍灰底、青色點綴、等寬無襯線數字，質感偏 app。全部以 CSS 實作，**不使用任何圖片素材**（含 icon，改用 CSS 繪製或文字符號）。

### 9.1 色彩 Token

| Token | 色碼 | 用途 |
| --- | --- | --- |
| `--bg` | `#0F172A` | 頁面底色 |
| `--surface` | `#1E293B` | 盤面 / 面板 / 卡片底色 |
| `--surface-raised` | `#334155` | 選中格、hover 狀態 |
| `--border` | `#334155` | 格線（細） |
| `--border-strong` | `#64748B` | 宮線（粗）、盤面外框 |
| `--text` | `#E2E8F0` | 主要文字、初始題目數字 |
| `--text-muted` | `#94A3B8` | 次要文字（HUD 標籤、說明） |
| `--accent` | `#22D3EE` | 玩家填入的正確數字、選中格外框、主要按鈕 |
| `--accent-dim` | `#0E7490` | 按鈕 hover / 邊框弱化 |
| `--danger` | `#F43F5E` | 錯誤的紅色 X、剩餘機會歸零警示 |

### 9.2 字體

- **FR-11.1** 數字（盤面、數字面板、計時器）使用**等寬無襯線**字體，確保數字寬度一致、計時器跳動時不位移。
  字體堆疊：`ui-monospace, "SF Mono", "JetBrains Mono", Menlo, Consolas, monospace`
- **FR-11.2** 標題與按鈕使用系統無襯線字體堆疊：`system-ui, -apple-system, "Segoe UI", "Noto Sans TC", sans-serif`
- **FR-11.3** 彈窗英文標題（`Welcome Sudoku` / `Menu` / `Congratulations!` / `Oops!`）採較大字級、字重 600–700。

### 9.3 盤面與格子

- **FR-12.1** 盤面底色 `--surface`，外框 2px `--border-strong`，整體圓角 8px。
- **FR-12.2** 格線 1px `--border`；宮線（每 3 格）2px `--border-strong`。
- **FR-12.3** 格子狀態的視覺定義：
  | 狀態 | 底色 | 數字顏色 | 其他 |
  | --- | --- | --- | --- |
  | 初始題目（給定數字） | `--surface` | `--text` | 字重 600 |
  | 空格 | `--surface` | — | — |
  | 空格 hover | `--surface-raised` | — | 游標 pointer |
  | 選中格 | `--surface-raised` | — | 2px `--accent` 外框 |
  | 玩家填對 | `--surface` | `--accent` | 字重 500，帶極淡光暈 `text-shadow: 0 0 8px rgba(34,211,238,.35)` |
  | 錯誤 X | `--surface` | `--danger` | 見 FR-8.4 動畫時序 |
  | 鎖定格 hover | 不變 | 不變 | 游標 default，無 hover 效果 |
- **FR-12.4** 初始題目與玩家填對的數字，靠**顏色**區分（淺灰 vs 青色），符合 FR-8.2 的可區分要求。

### 9.4 HUD

- **FR-13.1** HUD 與盤面同寬，置於盤面上方，左右分區（見 FR-4.1）。
- **FR-13.2** 難度、計時器、剩餘次數的標籤文字用 `--text-muted`，數值用 `--text`。
- **FR-13.3** 剩餘答錯次數以 **3 個小方塊或圓點**呈現：未用 `--text-muted`、已用 `--danger`（或熄滅）。剩 1 次時整組以 `--danger` 強調。
- **FR-13.4** 暫停鍵以 CSS 繪製的「‖」符號呈現，不使用圖檔。

### 9.5 數字面板

- **FR-14.1** 面板底色 `--surface`，1px `--border-strong` 外框，圓角 8px，陰影 `0 8px 24px rgba(0,0,0,.45)`。
- **FR-14.2** 3×3 排列，每顆數字按鈕為方形，數字用 `--text`。
- **FR-14.3** hover 時按鈕底色 `--surface-raised`、數字轉 `--accent`。
- **FR-14.4** 面板出現時帶 120ms 的淡入 + 輕微上移（或下移，依 FR-7.3 的方位）。

### 9.6 彈窗

- **FR-15.1** 遮罩：`background: var(--overlay)` + `backdrop-filter: blur(8px)`，覆蓋全畫面。深色底搭配模糊可有效遮蔽盤面（呼應 FR-0.2）。
- **FR-15.2** 對話框：`--surface` 底、1px `--border-strong` 外框、圓角 16px、陰影 `0 24px 64px rgba(0,0,0,.6)`，置中。
- **FR-15.3** 進場動畫：遮罩淡入 200ms；對話框淡入 + 由 0.96 放大至 1，200ms。
- **FR-15.4** 按鈕樣式：
  | 類型 | 樣式 | 用於 |
  | --- | --- | --- |
  | 主要 | `--accent` 底、深色字 | 繼續遊戲、三個難度按鈕 |
  | 次要 | 透明底、1px `--border-strong` 邊框、`--text` 字 | 重新開始、另開新局、重選難度 |
- **FR-15.5** M2 完成彈窗的總時間以大字級等寬字體呈現，顏色 `--accent`。
- **FR-15.6** M3 失敗彈窗標題 `Oops!` 使用 `--danger`。

### 9.7 Skeleton Loading

- **FR-16.1** skeleton 以 `--surface` 底、`--surface-raised` 方塊呈現 9×9 格與 HUD 區塊，維持與實際盤面相同的尺寸與間距，避免切換時位移。
- **FR-16.2** 律動效果採 shimmer：`--surface-raised` 與略亮色之間的漸層橫掃，週期 1.5s 循環。

### 9.8 動態效果與無障礙（Reduced Motion）

- **FR-17.1** 支援作業系統的「減少動態效果」設定，以 `@media (prefers-reduced-motion: reduce)` 偵測。
- **FR-17.2** 此模式下的替代方案：

  | 動畫 | 一般模式 | Reduced Motion 模式 |
  | --- | --- | --- |
  | 錯誤 X | headShake 左右晃動 0.6s | **不晃動**，紅色 X 靜態停留 0.9s；同時該格底色以 `--danger` 低透明度（約 15%）淡入淡出一次 |
  | 彈窗進場 | 淡入 + 由 0.96 放大至 1，200ms | 僅淡入 200ms，不縮放 |
  | 數字面板出現 | 淡入 + 輕微位移 120ms | 僅淡入 120ms，不位移 |
  | Skeleton | shimmer 漸層橫掃 1.5s 循環 | 整塊明暗緩慢脈動 2s 循環，無橫向移動 |

- **FR-17.3** 錯誤回饋在此模式下的時序（T=0 為填入瞬間），**總長維持 1.2s 不變**：

  | 時間點 | 行為 |
  | --- | --- |
  | T = 0 | 數字正常顯示於空格中 |
  | T = 0.3s | 數字被紅色 X 取代；該格底色紅色淡入 |
  | T = 0.3s – 1.2s | 紅色 X 靜態停留（0.9s），底色紅色於期間淡出 |
  | T = 1.2s | X 消失，該格恢復為空格 |

- **FR-17.4** 兩種模式的**時序總長一致（1.2s）**，FR-8.5（T=0.3s 扣除次數）與 FR-8.7（動畫播完才顯示 M3）的邏輯共用，不因模式而分岔。
- **FR-17.5** Reduced Motion 模式下**不得直接移除錯誤回饋**。錯誤動畫承擔「告知玩家填錯並失去一次機會」的功能性回饋，必須以不含位移的方式（顏色、停留時間、不透明度）等效呈現。
- **FR-17.6** 右上角剩餘次數的點在扣除時，兩種模式皆以顏色轉換強調，不使用位移或縮放動畫。

### 9.9 響應式尺寸

- **FR-18.1** 斷點定義：
  | 名稱 | 寬度 | 目標裝置 |
  | --- | --- | --- |
  | mobile | ≤ 480px | 手機直向 |
  | tablet | 481–768px | 手機橫向、小平板 |
  | desktop | > 768px | 平板橫向、桌機 |

- **FR-18.2** 盤面尺寸以單一公式驅動，不同斷點間連續縮放，避免跳階：

  ```css
  --board-size: min(92vw, calc(100vh - 180px), 540px);
  --cell-size: calc(var(--board-size) / 9);
  ```

  | 裝置 | 實際盤面 | 單格 |
  | --- | --- | --- |
  | iPhone SE（375px） | 345px | ≈ 38px |
  | iPhone 15（393px） | 361px | ≈ 40px |
  | iPad（768px） | 540px（觸及上限） | 60px |
  | 桌機 | 540px | 60px |

  - `92vw` 保證左右各留約 4% 邊距；
  - `100vh - 180px` 預留 HUD 與上下留白，確保**不需垂直捲動**；
  - `540px` 為上限，避免大螢幕上盤面過大而需要大幅移動視線。

- **FR-18.3** 盤面數字字級隨格子縮放：`font-size: calc(var(--cell-size) * 0.55)`（375px 上約 21px，桌機約 33px）。
- **FR-18.4** 數字面板按鈕的尺寸**不隨盤面縮放**，固定為最小 **44×44px**（符合觸控目標的通用最小值），面板整體寬度約 **156px**（3 × 44 + 2 × 8 間距 + 2 × 4 內距）。
  > 面板按鈕若跟著格子縮到 38px，在手機上會難以準確點擊，因此刻意與盤面脫鉤。
- **FR-18.5** 手機上數字面板（約 156px）明顯窄於盤面（約 345px），FR-7.3 的邊緣判斷足以將面板安置於不遮住目標空格的位置。
- **FR-18.6** HUD 在所有斷點皆維持左右分區的單行排列，與盤面同寬；mobile 下縮小字級與間距，不改為堆疊。
- **FR-18.7** 彈窗寬度：`min(88vw, 400px)`，內部按鈕在 mobile（≤480px）改為**垂直堆疊、滿寬**，desktop 則水平並排。
- **FR-18.8** 所有頁面內容在任何斷點皆不得出現橫向捲動。
- **FR-18.9** 觸控裝置上沒有 hover 狀態，FR-12.3 與 FR-14.3 的 hover 效果以 `@media (hover: hover)` 包裹，避免在觸控裝置上產生點擊後樣式殘留。

## 10. 技術實作規格

### 10.1 產題與 Web Worker

- **FR-19.1** 題目產生（含正解生成、挖空、唯一解驗證）一律在 **Web Worker** 中執行，不佔用主執行緒。
  > 困難難度需反覆呼叫解題器驗證唯一解，在主執行緒上可能造成數百毫秒的畫面凍結，連 skeleton 的 shimmer 動畫都會卡住——反而讓載入看起來像當機。
- **FR-19.2** 訊息協定：
  | 方向 | 訊息 | 內容 |
  | --- | --- | --- |
  | 主執行緒 → Worker | `generate` | `{ difficulty: 'easy' \| 'medium' \| 'hard' }` |
  | Worker → 主執行緒 | `result` | `{ puzzle: number[81], solution: number[81], givens: number }` |
  | Worker → 主執行緒 | `error` | `{ message: string }` |
  > `0` 表示空格。
- **FR-19.3** 主執行緒僅保留 `solution` 供 FR-8.1 即時判定使用，不再重複執行任何解題運算。
- **FR-19.4** Worker 生命週期：每次產題建立（或重用）一個 Worker，收到 `result` 後即可閒置備用。
- **FR-19.5** **競態處理**：若產題尚未完成，玩家已透過「重選難度」等操作離開 `generating` 狀態，則**終止該 Worker**（`terminate()`）並丟棄其結果，不得將過期題目套用到新的一局。
- **FR-19.6** **降級機制**：若執行環境不支援 Web Worker，改於主執行緒同步產題，功能不受影響（僅可能短暫卡頓）。
- **FR-19.7** **逾時處理**：單次產題若超過 **10 秒**仍未完成，視為異常，終止並重新產題；連續失敗 3 次則進入 `error` 狀態並顯示錯誤彈窗 M4（見 FR-20）。
- **FR-19.8** FR-2.6 的 skeleton 最短顯示時間 600ms 仍適用：即使 Worker 在 80ms 內回傳結果，仍須顯示滿 600ms。
